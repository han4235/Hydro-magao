# Step 4: 生题面

## 目标

生中文题面 `{WORK_DIR}/problem_zh.md`。

## 铁律：仅译不编

1. 仅译，保原构
2. 禁 AI 内心戏：禁分析、推理、计算过程
3. **样例解释**：原题有则必译，无则省略该节
4. **说明/提示**：原题有则必译，无则省略该节；数据范围若原题写在此节内，一并保留
5. **禁改样例**：题面已内联的样例输入/输出必原封不动复，不增删改任一字。题面**未内联**样例数据的（如洛谷题目页，样例在页面 JS 数据里，正文看不到）不适用本条：改按题面约束自造一组最小样例，不得因此略过该题
6. **留图片链**：题面中图片链接（如 `![](url)` 或 `<img>` 标签）必原样留，不删不替
7. **留示意**：题面原有示意图、表格、公式等必完整留

## 标题格式

`中文标题(英文原标题)`

**禁**带 `GESP X级｜` 之类前缀（标题只写题目名；级别由 tag 承载，见 `05-config.md`）。

例：
- `移除前导o(Trimo)`
- `传感器数据记录(Sensor Data Logging)`

## 题面格式

小节顺序固定如下；**原题没有的节可省略，但原题有的节不得漏**。

```markdown
<div class="water">

# 中文标题(英文原标题)

#### 题目描述
[中文翻译]

#### 输入格式
...

#### 输出格式
...

#### 样例输入 #1
...

#### 样例输出 #1
...

#### 样例解释 #1
[仅译原题对该样例的解释；原题无则整节省略]

#### 样例输入 #2
...

#### 样例输出 #2
...

#### 样例解释 #2
[多组样例时，每组输入/输出后紧跟对应解释]

#### 说明/提示
[译原题「说明/提示」「提示」「Hint」「Note」等小节全文；
 含数据规模、部分分、特殊约定、背景补充等；原题无则整节省略]

#### 数据范围
[仅当原题独立列出「数据范围」且未并入「说明/提示」时使用；
 若原题已在「说明/提示」中给出约束，则不再重复单列本节]

</div>
```

## 各节细则

### 样例解释

| 规则 | 说明 |
|------|------|
| 来源 | 原题「样例解释」「解释」「Explanation」等 |
| 位置 | 紧跟对应 `样例输出 #N` 之后 |
| 编号 | 与样例组号一致：`样例解释 #1` 对应 `样例输入/输出 #1` |
| 内容 | 仅译原题解释，禁自行推导或补充过程 |
| 缺失 | 原题无解释 → 不写该节，**禁 AI 编造** |

### 说明/提示

| 规则 | 说明 |
|------|------|
| 来源 | 原题「说明/提示」「提示」「Hint」「Notes」「Constraints」等 |
| 内容 | 数据规模、部分分、时空限制、特殊性质、背景补充、实现提示等 |
| 数据范围 | 洛谷等常将「对于 100% 的数据…」写在此节 → **保留在此节，勿拆散或删改** |
| 缺失 | 原题无此节 → 不写；若仅有独立「数据范围」→ 用 `#### 数据范围` |

### 多组样例

每组固定三连：

```
#### 样例输入 #N
#### 样例输出 #N
#### 样例解释 #N   ← 原题有则写，无则跳过
```

## 取后自检（写入前必核）

1. 标题与 PID 一致
2. 各组样例输入/输出与原题逐字一致
3. 原题有的样例解释已全部译入
4. 原题有的说明/提示（含数据规模）已全部译入
5. 图片、公式、表格未遗漏

## 更名工作目录（要务！）

生题面后，**将标题加入工作目录名**，增辨识：

```bash
# 定标题简写：
# - 英文标题：取全标题，空格→下划线，转小写
# - 中文标题：取前 4~8 字
# 例：标题为"移除前导o(Trimo)" → 简写为"移除前导o_Trimo"
#      标题为"Sensor Data Logging" → 简写为"sensor_data_logging"

mv {WORK_DIR} {WORK_DIR}_{标题简写}
# {WORK_DIR} = {WORK_DIR}_{标题简写}
```

> **注**：若 PID 为 null（原创题），径用标题简写：
> ```bash
> mv work work_{标题简写}
> # {WORK_DIR} = work_{标题简写}
> ```
