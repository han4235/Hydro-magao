# Step 2: 获取题目信息

## 目标

根据输入来源获取题目信息（PID、标题、题面内容）。

## 浏览器工具优先级

```
1. urlgo（优先）
2. BrowserUse（urlgo 不可用）
3. WebFetch（以上都不可用，仅公开页面）
```

## URL 抓取流程（新增铁律）

访 URL 时，不得只凭首屏可见文本手抄题面，必须按下序：

1. **开页面，先核身份**：确认最终 URL、页面标题、题号、平台名一致。
2. **先找结构化数据**：优先查页面内嵌脚本、状态对象、SSR 数据、公开 API 返回。若能直接取到 `title / description / input / output / samples / hint / limits` 等字段，径用之。
3. **再取正文文本**：结构化数据无或不全，方自正文 DOM / snapshot / innerText 分段抽取，并按标题小节重组。
4. **保全原信息**：样例、**样例解释**、**说明/提示**、图片链接、公式、表格、数据范围、特殊说明必完整保留，不得因抓取方式改变而丢字段。
5. **分层回退**：浏览器结构化提取失败 → 浏览器正文提取 → WebFetch 等公开抓取；每退一层都要核样例与小节齐全。

## 结构化提取优先项

优先查以下信息源：

- 页面内嵌 JSON（如脚本中 `currentData`、`__NEXT_DATA__`、`window.__INITIAL_STATE__`）
- 公开题面接口返回
- SSR 直出 HTML 中的题面字段
- 最后才是页面可见正文文本

## 取后必核

至少核六项：

1. 标题与 PID 是否一致
2. 样例输入输出是否完整
3. 各组样例解释是否完整（原题有则必取）
4. 说明/提示是否完整（含数据规模、部分分等，原题有则必取）
5. 输入格式 / 输出格式 / 数据范围是否齐
6. 题面中的图、表、公式是否被漏掉

## 来源类型

| 类型 | 处理 |
|------|------|
| URL | 开页核标题 → 优先取结构化数据 → 不足则补正文 → 最后公开抓取 |
| 题号 | 直接匹配 PID 格式 |
| 文件 | 解析文件提取题目信息 |
| 文本 | 解析用户给出的文本 |

## PID 提取

| 平台 | URL 格式 | PID 规则 |
|------|---------|---------|
| AtCoder | `/contests/abc451/tasks/abc451_a` | `abc451a` |
| Codeforces | `/contest/71/problem/A` | `cf71a` |
| LeetCode | `/problems/two-sum` | `lc1` |
| Luogu | `/problem/P1001` | `p1001` |

无法提取时 PID 填 `null`。

## 重命名工作目录（关键！）

提取到 PID 后，**立即重命名工作目录**，使其包含题目标识：

### 如果当前目录是 `work`（即初始化时PID未知）：

```bash
mv work work_{PID}
# {WORK_DIR} = work_{PID}
```

### 如果当前目录已经是 `work_{PID}`（即初始化时已用PID）：

无需操作，`{WORK_DIR}` 保持不变。

### 如果 PID 为 null（无法提取）：

保持 `{WORK_DIR}` 不变，后续步骤确定名称后再处理。
